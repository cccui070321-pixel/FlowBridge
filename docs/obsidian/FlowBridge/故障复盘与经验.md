# 故障复盘与经验

## 1. 邮箱确认链接跳到 localhost

**表现：** QQ 邮箱点击确认后打开 `http://localhost:3000`，页面空白或网络断开。

**原因：** Supabase Auth 的 Site URL/Redirect URL 仍指向开发地址，而当时本机没有运行该地址。

**经验：** 认证链路必须区分开发回调和正式客户端回调；发布前要用真实邮箱、真实设备完整走一遍注册与确认。

## 2. 所有文件在 SHA-256 阶段失败

**错误：** `WebAssembly.compile()` 违反 Content Security Policy。

**原因：** `hash-wasm` 在计算哈希时编译 WebAssembly，而 CSP 只有 `script-src 'self'`。

**修复：** 增加 `wasm-unsafe-eval`，不开放普通 `unsafe-eval`。

**经验：** 安全策略不能只做静态检查；所有用到 WASM、Worker、Blob URL 的依赖都要在打包后的 Electron 环境验证。

## 3. 106.9MB 文件返回 413

**错误：** `Maximum size exceeded`。

**原因：** Supabase Free 的单对象上限为 50MB。TUS 的“分片传输”是协议层断点续传，并不等于把一个对象拆成多个存储对象。

**修复：** FlowBridge 自己把大文件拆成 45MB 对象，另存清单，接收端自动合并和 SHA-256 校验。

**经验：** 产品上限必须由最小平台上限决定，不能只看 SDK 宣称能力。

## 4. 中文文件名返回 400 Invalid key

**错误路径示例：** `用户ID/传输ID/微信图片_....jpg`。

**原因：** Supabase Storage key 对字符有约束，中文原文件名不适合直接作为对象名。

**修复：** 云端使用 `file.jpg` 等内部名；中文原名继续存入 `original_name`，接收保存时恢复。

**经验：** “展示名称”和“内部标识”必须分离。数据库主键、对象 key、URL path 都不应依赖用户输入名称。

## 5. 旧失败记录的重试不等于重新上传

当前失败记录只保留元数据，不一定还持有浏览器 `File` 对象。仅把状态改回“等待上传”无法恢复真实文件内容。

**短期操作：** 用户升级后重新选择原文件。

**产品改进：** 重试按钮应检测本地句柄是否存在；不存在时打开文件选择器，并明确提示“请重新选择原文件”。

## 6. 自动更新在编译通过后仍导致安装版启动崩溃

**错误：** `Named export 'autoUpdater' not found`。

**原因：** `electron-updater` 是 CommonJS 模块；TypeScript 与开发编译允许命名导入，但 Electron 安装包按 ESM 载入主进程时不接受该写法。

**修复：** 改用默认导入，再从模块对象解构 `autoUpdater`，重新生成 NSIS 安装包。

**经验：** `typecheck`、单元测试和开发模式全部通过仍不代表桌面安装包可启动。每次新增主进程依赖，都必须安装最终产物并真实启动一次。

## 7. Windows 旧“所有用户安装”可能卡住覆盖安装

**表现：** NSIS 覆盖安装停住，旧 FlowBridge 后台进程仍占用安装目录，并出现系统权限确认。

**处理：** 发布前先从托盘退出旧进程；若系统弹出权限确认，必须由用户本人允许，不能由自动化绕过。

**经验：** 自动更新测试要同时覆盖“当前用户安装”和历史“所有用户安装”，并确保安装前正确退出后台主进程。

## 系统性改进

- 在发布前建立固定测试矩阵：ASCII/中文/空格/括号/长文件名；
- 文件大小覆盖：1KB、1MB、44MB、46MB、100MB、500MB 边界；
- 文件类型覆盖：JPG、DOCX、MP4、ZIP、EXE；
- 两台真实设备分别测试发送、接收、离线补收和取消；
- 错误信息从 SDK 原文转换成中文行动建议；
- 增加传输诊断日志，但不得记录文件内容、Token 或签名 URL。
